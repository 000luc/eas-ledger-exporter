# 金蝶EAS批量序时账导出工具设计

## 目标

用本机Python程序替代影刀RPA，批量从金蝶EAS导出凭证序时簿。

程序只负责序时账导出，不执行内部交易、外部交易、往来核对或邮件发送。运行期间EAS可以保持打开并最小化，正常情况下不占用鼠标和键盘。

## 输入

沿用 `D:\内部交易rpa\info.xlsx`：

- `执行期间`：读取年份、月份和文件保存路径。
- `执行操作的公司`：读取公司编号、公司名称和是否执行。
- 只处理“是否执行”为“是”的公司。
- 忽略内部交易、外部交易、往来核对等开关。

## 技术方案

采用Python和Windows UI Automation操作EAS控件，不依赖固定屏幕坐标。

优先按窗口标题、控件类型、可访问名称和父子关系定位控件。个别EAS控件若无法直接识别，可使用窗口内快捷键作为补充，但不使用全屏坐标点击或图像识别作为主流程。

程序划分为以下模块：

- 配置读取：读取并校验 `info.xlsx`。
- EAS连接：查找已登录的EAS主窗口并确认可操作。
- 查询控制：打开凭证查询、填写查询条件并执行查询。
- 导出控制：打开右键菜单，执行“导出到Excel”，处理导出向导。
- 文件处理：等待文件生成、确认写入完成并修正工作表范围。
- 结果校验：核对文件内容、公司、期间和表头。
- 运行记录：记录每家公司状态、耗时、文件路径和错误现场。

## EAS操作流程

首次进入：

1. 找到已登录的金蝶EAS主窗口。
2. 依次进入“财务会计 → 总账 → 凭证处理 → 凭证查询”。
3. 等待“凭证-条件查询”窗口出现。

每家公司：

1. 在“公司”字段选择目标公司。
2. 选择“按期间查询”。
3. 将起始和结束会计期间都设为配置中的同一年、同一月。
4. 将“最大返回结果数”设为“全部”。
5. 审核状态、过账状态、复核状态均选“全部”。
6. 选择“按凭证查询”。
7. 点击“确定”，等待“凭证序时簿”结果表加载完成。
8. 在结果表打开右键菜单，选择“导出到Excel”。
9. 在导出向导中填写目标文件路径并执行导出。
10. 等待文件生成并完成校验。
11. 点击工具栏“条件查询”，进入下一家公司。

## 文件命名

输出文件名沿用现有规则：

`公司编号.公司名称_年月_凭证序时簿.xlsx`

例如：

`001.广州本部_202606_凭证序时簿.xlsx`

年月固定使用六位 `YYYYMM`，避免现有 `20265` 这类不明确格式。

开始导出某家公司前，仅删除该公司、该期间的同名旧文件，不清空整个输出目录。

## 导出完成判断

程序不使用固定时长判断导出完成，而是同时检查：

- 目标文件已经出现。
- 文件能够以共享读取方式打开。
- 文件大小连续两个检查周期保持不变。
- EAS导出向导已关闭或显示导出成功。

大文件允许配置较长超时时间。超时后立即停止，不自动重试。

## 工作表范围修正

现有EAS导出文件的 `sheet1.xml` 中可能把工作表范围错误写为 `A1`，导致部分程序只能读到第一个单元格。

导出完成后，程序读取工作表XML中实际最后一个单元格坐标，把 `dimension ref` 修正为真实范围，例如 `A1:AB12345`。修正时保留原工作簿其他内容，并先写入临时文件，成功后再替换原文件。

## 自动校验

每个文件必须通过以下检查：

- 文件存在且大小大于零。
- 工作簿能够正常打开。
- 工作表包含28列标准表头。
- 表头包含“公司”“记账日期”“期间”“凭证类型”“凭证号”“科目编码”“科目名称”“借方”“贷方”等关键字段。
- 有数据时，所有非空“公司”值属于目标公司。
- 有数据时，所有非空“期间”值等于目标年月。
- 文件名中的公司编号、公司名称和年月与配置一致。

若查询结果确实为零行，记为“空数据成功”，仍生成并校验仅含表头的文件。程序必须先根据EAS结果表的空数据状态确认，不能仅因导出文件没有数据就判定为空数据成功。

## 失败处理

任何一步失败都立即停止，不跳过公司，不自动重试。

停止时：

- 保留EAS当前窗口和查询现场。
- 不删除已成功导出的文件。
- 记录失败公司、当前步骤、窗口标题、错误信息和时间。
- 截取EAS窗口保存到日志目录。
- 在控制台明确显示需要人工检查的步骤。

常见失败包括：

- EAS未启动或未登录。
- 控件无法定位或状态不正确。
- 公司选择失败。
- 查询超时或EAS弹出异常窗口。
- 导出向导异常。
- 文件写入超时。
- 工作表修正失败。
- 公司、期间、表头或数据行校验失败。

## 日志

每次运行建立独立日志目录，保存：

- 文本运行日志。
- CSV格式公司执行汇总。
- 失败时的EAS窗口截图。
- 本次读取的年份、月份、输出路径和公司清单。

汇总状态限定为：

- 成功
- 空数据成功
- 失败
- 未执行

## 测试

自动测试：

- `info.xlsx`配置读取和错误提示。
- 文件命名及年月格式。
- EAS导出文件工作表范围识别和修正。
- 标准文件、空数据文件、公司错误、期间错误、表头缺失和损坏文件校验。
- 文件大小稳定判断和超时处理。

现场验收：

1. 使用1家公司运行，人工核对查询条件、导出文件和日志。
2. 使用3家公司连续运行，验证公司切换及失败停止。
3. 使用全部启用公司运行，核对文件数量和汇总状态。
4. 运行期间使用鼠标和键盘操作其他程序，确认EAS不会持续抢占输入。

## 完成标准

- 能读取现有 `info.xlsx` 并批量处理启用公司。
- 正确设置公司、期间及全部查询选项。
- 每家公司生成命名统一且可被常用Excel工具完整读取的文件。
- 自动校验公司、期间、表头和数据状态。
- 任一失败立即停止并保留可定位的现场和日志。
- 除必要的EAS窗口激活外，不持续占用鼠标和键盘。
